# File storage

```bash
gemstack add storage
```

Switches on `require "gemstack/storage"` in `config/app.rb` and adds `POST /api/uploads` (`UploadsController`),
`frontend/lib/upload.ts` and test helpers. Files go **straight from the
browser to storage** — never through a Ruby process, so `max_body_size` stays
small and uploads don't tie up server threads.

```tsx
import { uploadFile } from "@/lib/upload";

const { signedId } = await uploadFile(file, { onProgress: setProgress });
await products.update(id, { image: signedId });
```

```ruby
class ProductsController < ApplicationController
  def update
    product = Product.find(params[:id])
    product.update(image_key: GemStack::Storage.key_for_signed_id(params[:image])) if params[:image]
    render product
  end
end

class ProductSerializer < ApplicationSerializer
  attribute :image_url, :string, nullable: true do |product|
    product.image_key && GemStack::Storage.url(product.image_key)   # signed, expires in 5 minutes
  end
end
```

1. `POST /api/uploads { filename, content_type, byte_size }` — the server checks
   the type and size and answers `{ signed_id, url, method, headers }`.
2. The browser `PUT`s the file to `url`. The URL's signature covers the content
   type and the exact size; it expires after 5 minutes.
3. The record stores the key behind `signed_id`. A tampered `signed_id` is a 422,
   so clients can't attach files that aren't theirs.

## Services

| | Development / tests | Production |
| --- | --- | --- |
| Service | `:disk` — files under `storage/` (git-ignored) | `:s3` — S3, Cloudflare R2, MinIO… |
| URLs | signed `/api/storage/…` URLs served by the API | presigned S3 URLs |

```bash
# production
STORAGE_SERVICE=s3
S3_BUCKET=shop-uploads
AWS_REGION=eu-west-3
AWS_ACCESS_KEY_ID=… AWS_SECRET_ACCESS_KEY=…     # or an instance role
S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com   # S3-compatible services only
```

Add `gem "aws-sdk-s3"` to the Gemfile, and allow the browser's `PUT` in the
bucket's CORS configuration:

```json
[{ "AllowedOrigins": ["https://shop.example"], "AllowedMethods": ["PUT"],
   "AllowedHeaders": ["content-type"], "MaxAgeSeconds": 3600 }]
```

## Configuration

```ruby
config.storage.max_upload_size = 25 * 1024 * 1024
config.storage.allowed_content_types = %w[image/* application/pdf]   # default: common images + PDF
config.storage.url_expires_in = 300
```

## Security

- Keys are generated by the server (`uploads/2026/09/<uuid>/<name>.<ext>`); the
  extension always matches the validated content type, so `evil.html` declared
  as `image/png` is stored as `evil.png`.
- SVG and HTML are not accepted by default — they can carry scripts.
- Files served by the disk endpoint carry `X-Content-Type-Options: nosniff`
  and `Content-Security-Policy: sandbox`; only images, PDFs and plain text are
  shown inline, anything else downloads.
- Signed URLs and `signed_id`s use `SECRET_KEY_BASE` (generated automatically
  in development and tests; required in production: `openssl rand -hex 64`).

## Server-side files

```ruby
GemStack::Storage.upload("exports/report.csv", io, content_type: "text/csv")
GemStack::Storage.download(key)
GemStack::Storage.url(key, disposition: "attachment", filename: "report.csv")
GemStack::Storage.delete(key)
```

## Testing

Tests use a temporary disk service, cleared after each test:

```ruby
signed_id = upload_fixture(File.binread("test/fixtures/cat.png"), filename: "cat.png")
patch_json "/api/products/#{product.id}", { image: signed_id }
```
